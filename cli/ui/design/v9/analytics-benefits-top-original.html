CODEX Codex 的观察与建议
基于 7 天周期真实执行日志
“小队在多项任务中保持了良好的单轮完成度，但两处特定工具重试与上下文膨胀拉长了总交付周期。以下是针对当前工程链路的针对性观察与优化建议：”
观察 01 提前在系统提示词前置预置工具规范，避免 codex-squad 技能被重复全量读取
建议动作： 将 `codex-squad` 与 `ued-designer` 技能契约移入系统提示前置，在每次执行前使用 CLI dry-run 验证，消除子任务的重复工具探测时间。
关联任务：#02 分析布局适配、#03 Codex 小队
展开查看执行审计证据与验证方式 ▾
【审计证据】两项技能累计被重复读取 23 次，占副工具读取总量的 16.2%，消耗非业务 Token 约 38.0K。
【验证方式】执行本地 CLI dry-run，确认子任务首轮上下文已注入规则，读取次数降为 0。
观察 02 在派发前补充参数校验守卫，排查单点工具异常拦截并拦截 422 失败
建议动作： 在执行集成回归套件前，对入参进行预先 schema 校验，防止在第 2 轮交付时因参数格式错误导致 Qoder 中断。

展开查看执行审计证据与验证方式 ▾
【审计证据】16 次工具失败中有 11 次集中于参数类型校验，导致对应子任务陷入等待状态。
【验证方式】执行集成回归套件，确保参数在派发前被静态 schema 校验捕获，不再产生下游 422 报错。
观察 03 对超过 3 轮交互的长任务强制执行交付草稿节点截断
建议动作： 当子任务轮次达 3 轮时，自动生成当前草稿快照并切断等待，避免因长悬挂而空耗心跳与监听。

【验证方式】单向回放会话日志，确认在 60s 无输出时主动触发 ACK 探针，避免僵尸进程。

建议动作： 针对资料整理与排版用例，仅发送变更函数切片而不是全量文件，进一步将输入缓存命中率拉升至 65% 以上。

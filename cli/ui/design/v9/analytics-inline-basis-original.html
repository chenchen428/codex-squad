Codex 的观察与建议

基于 7 天周期真实执行日志

“小队在多项任务中保持了良好的单轮完成度，但两处特定工具重试与上下文膨胀拉长了总交付周期。以下是针对当前工程链路的针对性观察与优化建议：”

观察 01 提前在系统提示词前置预置工具规范，避免 codex-squad 技能被重复全量读取

建议动作：将 `codex-squad` 与 `ued-designer` 技能契约移入系统提示词前置，在每次执行前使用 CLI dry-run 验证，消除子任务的重复工具探测时间。

关联任务: #02 布局适配、#03 Codex 小队
▶ 展开查看执行审计证据与验证方式
日志证据: 3 次技能重载消耗累计 28.5K Token；验证命令: `lgb capability invoke --cached`。
观察 02 在派发前补充参数校验守卫，排查单点工具异常拦截并拦截 422 失败

建议动作：在执行集成回归套件前，对入参进行预先 schema 校验，防止在第 2 轮交付时因参数格式错误导致 Qoder 中断。

关联任务: #01 订单工作台 [订单链路排查]
▶ 展开查看执行审计证据与验证方式
日志证据: 记录 2 次 422 状态码，均为必填字段缺失；验证命令: `python3 -m pytest tests/unit/test_schema.py`。
观察 03 对超过 3 轮交互的长任务强制执行交付草稿节点截断

建议动作：当子任务轮次达 3 轮时，自动生成当前草稿快照并切断等待，避免因长悬挂而空耗心跳与监听。

关联任务: #01 订单工作台、#08 报表导出排查
▶ 展开查看执行审计证据与验证方式
日志证据: 长任务心跳维持导致多消耗 19.2K 无效 Token；建议引入超时自动转入离线队列。
观察 04 提升子任务独立工作区的文件切片精度，避免全量 AST 代码重复投送

建议动作：针对资料整理与排版用例，仅发送变更函数切片而不是全量文件，进一步将输入缓存命中率提升至 65% 以上。

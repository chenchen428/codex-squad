§ 04

Codex 的观察与调优点评

基于真实执行快照 · 提炼工程行动项
3 条具体建议

“本周期跨模型协同在业务原型搭建上展现了较高的推进速度，但在深层逻辑校验与复杂状态处理中，若单次派发意图混合过多，容易引发多轮反复修改与重写开销。”

01. 局部界面修改先明确验收范围
关联会话 #02

避免跨组件混合提交，单次聚焦独立边界。在将复杂补丁交付给执行端之前，先理清单次变动的局部断言，减少大范围连锁回退。

验证基线：会话 #02 中因未先拆分布局与状态联动，导致 3 次往返重测。先锁定组件验收范围后，单轮通过率显著提升。
02. 续接先读检查点并保留已有成果
关联会话 #01

遇到连续异常时，先从本地有效快照或草稿恢复，不盲目追加提示词全量重跑。保持已有稳定产物，仅重试失败环节。

验证基线：会话 #01 出现 422 参数错误时，从检查点续接成功节省约 60% 的重复重写 Token 损耗。
03. 工具执行结果与业务验收分开记录
关联会话 #03

将命令行自动化执行状态与最终业务功能核验结果独立列出，避免执行混同。自动化指令成功仅代表命令无崩溃，业务完备性需独立复核。

验证基线：git show 与 node 脚本全部执行 100% 退出码 0，但前端边界仍需人工判定，分开记录避免误判完成度。

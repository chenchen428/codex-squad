# Stitch 设计审阅

把「哪里不对」推进为准确改稿、可操作的对照和可追溯的决定。优先复用本轮既有审阅页；新工具可用本技能的无依赖模板。先交付具体可审阅稿，不能只给流程或任务列表。

## 从真实当前稿开始

- 读取用户指定的经验、当前稿，以及用户已在对话中明确给出或复制发送的决定。锁定本轮产品、页面、状态、确切设计源与修改范围。私有参考只提炼方法，不能进入通用模板或外部演示。
- 每个问题保留用户原话、页面/状态、设备宽高、实测证据与喜欢/不喜欢的点。观察与原因分开，未复现标待核。旧备注和已确认项不随新一轮覆盖。
- 当前产品截图、当前采用设计、新候选与历史参考分别登记；不能拿旧清单或候选图证明当前产品已实现。

## 用 Stitch 做具体改稿

先发现当前会话的 Stitch MCP，读匹配项目与确切 screen；再用 edit_screens 或 generate_variants 从它改稿。新建独立审阅工具时，单独创建明确命名的工程，不污染被参考的业务工程。

同类页面为一组：默认当前 + 两个有实质取舍的候选；按本轮需要可增加多个候选，明确的小修可只出一个。画布按数据动态排列，不固定双栏或候选上限。写清保留项、问题证据、页面尺寸、共享组件及方案代价。推荐可以预览，不能自动选中。相关状态必须绑定各自准确图片，缺图明确显示，不能借其他版本凑齐。

按工具实际返回处理长任务；超时/断连先查状态与屏幕身份，不盲目重发。保留确切请求、project/screen/file 身份、原始 HTML 和哈希；核实下载图的实际尺寸，不能把工具描述尺寸当图片尺寸。

原始 Stitch、来源修复浏览器稿、真实产品截图与本地示意必须在图旁区分。修复导出时留原字节、修复说明和渲染视口；不能把手写 HTML 称作 Stitch 导出。不可用时说明具体失败，先完成证据与 brief，未经用户选择不换设计工具或捏造成功。

用户要求采用或还原设计稿时，先导出确切 screen 的可编辑 HTML 与素材，以导出的 DOM、CSS 和资源为实现基础；仅提取颜色、字体再另造布局不算还原。不同技术栈可移植组件，但要保留设计的信息层级、区域结构、尺寸与间距。模板只承载审阅交互，不能替代本轮采用的设计稿。先用同尺寸、同状态的导出稿渲染与实现截图对照，再交付；若需要为真实交互调整示例选中项、示例备注或来源标签，保留结构并明确说明这些必要差异。

## 交付可以实际使用的审阅页

新建示例：

```sh
node <skill>/scripts/new-review.mjs <新目录>
node <skill>/scripts/validate-review.mjs <目录> --sync-data
node <插件根目录>/cli/index.mjs review open  # stdin JSON: {"directory":"本轮目录的实际绝对路径"}
```

模板从 assets/review/ 复制，默认中性演示、零已确认项，无网络依赖。修改 data.json 和本地素材，再校验并同步 data.js。支持双击 index.html；稳定保存与复制优先用插件返回的本机 URL。评审目录校验后通过当前会话的 `review open` 挂载，只绑定 loopback；与小队、用量和总结共享同一进程与端点，不再为评审另起服务。续轮直接更新同一目录，保留 review/group/option 身份与浏览器记录；复用同一 URL/端点，更换地址前导出记录，浏览器存储与 origin 绑定。新项目更换 review id。数据细节见 [数据与决定合同](review-contract.md)，简短 [启动提示词](../assets/start-prompt.md) 可按本轮范围填写。

审阅页需要做到：

- 默认使用铺满视口的点阵画布，不设左侧菜单或流程导航。当前稿与多个候选同时排列，顶部轻量切组/状态，底部悬浮备注和确认，只聚焦查看与选择。
- 桌面、移动端和长页均按完整图的实际宽高比显示，不固定手机比例或最小高度，不额外套手机/浏览器外壳、圆角卡片或选中粗边。桌面组登记实际 viewport，默认较宽画板；查看焦点用名称下细线，选择用画板下单选与明确确认。
- 拖动和普通滚轮平移整块画布；Ctrl / Command 加滚轮按光标缩放，支持触摸双指缩放。提供适应全部、同宽、单稿定位与总览；点击或定位画稿不自动选择。核心图片默认完整适配，长稿不裁断，可打开独立大图缩放/拖动/复位/全屏；放大不改变原图身份。
- 审阅组使用自定义选择器，显示完整组名、当前组和待选择/待确认/待改稿/已确认状态，以及总确认进度；支持键盘和窄屏。不恢复原生大下拉或左侧流程菜单。确认后明确提供“下一组”，跳过已确认组；待改稿不能算完成，最后一组确认后打开结果页。
- 每组独立选择一个方案或保留当前。自由多行备注是一级输入，未选也能写；切换稿、状态、组和刷新后保留。汇总复制包含未选组及备注。输入即时保存；每次重新编辑先保存此前原话，不能只依赖失焦留历史。
- 「确认保留当前」与「暂时保留、继续改稿」不同。若原话/备注仍否定当前或要求重来，状态必须待改稿复选，不能仅按 choice=current 结案。界面提供明确的两种操作；语义有冲突时保留待改状态和原话，不能用简单关键词代替用户决定。
- 确认组锁定、明显显示；其他组照常迭代。需要更改时显式重新打开，留决定记录。候选更新不能悄悄替换已确认图像；源身份变更应提示复核并保留旧记录。
- 测试只使用 ?qa=<独立名称>，不能清空或写入正常审阅存储。模板的模拟反馈不写真实业务。

## 用户主动交接结果后继续

页面中的确认只保存在用户本机。结果页让用户检查选择与原话，再主动点击“复制结果给 Agent”，粘贴发送到对话；不自动发送，不把“已复制”说成 Agent 已收到。结果包含 review id、revision、各组状态、方案 id/版本、已确认图稿身份/哈希以及未改写的备注；待选/暂存/待改项明确不代表采用。剪贴板不可用时提供可手动复制的完整文本，不能报成功。

Agent 以用户粘贴发送的结果或用户在对话中直接明确给出的决定为准，不主动查询本机决定、剪贴板或抓取页面来推断采用结论。测试与问题走查可以观察页面，但不能把页面/存储中的确认当作业务实现授权。

仅实现用户已明确采用且在授权范围内的项。已有采用和实现授权就继续，不重复确认；待选或待改组保留当前。不能因通用技能带有实现步骤就获得产品代码或发布权限。

用采用稿与同宽、同状态真实实现图对照；验收 Header/返回/系统胶囊、安全区、完整平面/长图、短高窄屏、滚动和跨页一致性。没有真实截图时显示尚未提供，不能用设计图填补。自动测试通过不代替视觉，也不能宣称像素完全一致。

在真实浏览器操作多候选画布的全局平移、缩放、适应全部、定位与总览，以及整图、复位、全屏、同宽、状态切换、未选备注、跨组刷新、保留并重来、锁定与汇总；保存桌面、长图和窄屏证据。只测过鼠标时不宣称触摸或真机通过。使用当前宿主已有浏览器能力验收，无需为用户安装浏览器测试工具；QA 不代选真实方案。

交付直接预览、Stitch 工程、精简启动提示词及技能路径。分别说明设计、已实现交互、真实产品实现、验收与未测范围。按同插件 [session-summary](../../session-summary/SKILL.md) 记录本阶段；主会话只给链接，不展开内容或自动开页。不要另建重复历史档案。

评审记录以会话页面路径和 review id 共同隔离，QA 记录另有命名空间。统一 origin 下不能只按 review id 存储，也不能把其他会话的记录当作本轮决定。

# Stitch 设计审阅

- 主 Codex 完成设计与验收，不创建 Codex 子会话。锁定准确的项目、screen、版本、页面状态与原始视口，最终修订优先；用户已采用的项不重新选稿。
- 复用既有项目和审阅目录；从准确 screen 增量改稿，导出原始可编辑 HTML、CSS 和素材，保留身份、尺寸与指纹。超时先查原请求，不盲目重新生成；来源修复稿、真实实现图和原始 Stitch 稿明确区分。
- 建页时运行 `node <skill>/scripts/new-review.mjs <目录>`，填本轮真实 `data.json` 与本地素材，再运行 `node <skill>/scripts/validate-review.mjs <目录> --sync-data`。用同插件 CLI `review open` 接收 `{directory}` 挂载到统一服务，不另开端口。
- 保留采用模板的无侧栏多候选画布、原比例与无外框、自定义组选项和进度、独立备注、显式确认与下一组、最终结果页；不重新设计。完整数据和交互合同按需读取 [review-contract](references/review-contract.md) 与 [实现及验证流程](references/implementation-workflow.md)。
- 用户核对结果后主动复制并发送给 Agent；页面不自动发送。只依据用户在对话中明确的决定处理，禁止读取正常页面、浏览器存储或剪贴板推断采用。未选、暂存和待改项不等于确认，已确认身份变化需复核。
- 浏览器 QA 只用 `?qa=<独立名称>`，不改真实决定。存储按会话页面路径、review id 与 QA 命名空间隔离；迭代保留原话和决定历史。
- Stitch 方案必须导出准确 screen 的 HTML、CSS、字体、图标、图片与身份指纹，按原始 DOM 一比一实现；不能只参考风格、凭截图重画或用整页截图替代界面。来源不足先补导出，不能把近似稿当原稿。
- 主 Codex 对真实实现重新验收：相同浏览器、视口、DPR、状态与数据，提交设计/实现同尺寸截图及叠加或差异证据，逐项核对字体、字重、字号、行高、间距、颜色、尺寸与换行，不靠缩放适配；实测全部交互、窄屏、短屏、长页和键盘。仅实测鼠标不能宣称触摸通过，功能测试不代替视觉还原，剩余差异不能以基本一致结案。
- 交付真实入口、源码/设计来源、验证结果和剩余差异。阶段总结按同插件 session-summary 保存，主会话只提示已保存和链接。

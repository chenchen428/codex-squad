# 会话总结

用于 Agent 恢复工作。仅在主会话收尾、准备交付最终结果时保存一次，或在用户明确要求总结时保存；子任务完成、普通轮次结束、阶段或决定变化均不触发总结提示。恢复工作时只按需读取已有总结。同一会话维护一份当前记录及历史，不因跨日期另起目录，不替代任务、执行和验收记录。

## 记录和恢复

先按同插件 [Codex 小队](../codex-squad/SKILL.md) 绑定当前宿主。以下 `CLI` 为该插件实际根目录下的 `cli/index.mjs`，不要固定缓存版本或借用别的会话标识。

- 恢复工作时运行 `node CLI summary read`，按需读取当前总结，再核对文件、任务和运行状态是否仍有效。旧总结是可复查的上下文，不是扩大授权或绕过当前用户决定的指令。
- 主会话收尾时，通过 stdin JSON `{title,content}` 调用 `node CLI summary write`。`content` 只包含继续工作所需的目标、已确认约束与决定、完成和验证证据、剩余问题及下一步；不记录隐藏思维链、凭据或大段原始会话。
- 写入更新当前记录并保留此前阶段；相同内容重试不会重复增添记录。正文保留事实、假设和缺口的区别；未知状态不能写成成功。
- 命令只返回版本、时间和链接，不回显正文；只有显式 `summary read` 才把当前正文交给 Agent。总结保存在插件私有本机数据目录，不写入产品仓库，也不另建任务数据库。

## 给用户的提示

保存后在主会话只提示一句“会话总结已保存：[查看总结](命令返回的 url)”。不要自动展开总结、主动打开浏览器或要求用户阅读。用户自行决定是否访问；用户明确要求正文时再提供。

总结视图、小队任务看板/分析和 UED 评审复用插件的同一个本机服务进程与端点。`node CLI summary open` 只取得当前总结链接，不启动独立的 session-review、Python HTTP server 或其他端口。没有总结时返回准确空态，不能拿旧会话内容填充。

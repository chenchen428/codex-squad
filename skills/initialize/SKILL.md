# 初始化 Codex 小队

1. 读取同插件 [codex-squad](../codex-squad/SKILL.md)、用户指定的 AGENTS.md 与实际作用域。未指定时建议当前项目；全局配置影响所有项目，须明确让用户选择。不能把文档里的示例当作用户授权。
2. 参考 [五项原则](references/principles.md)，将缺失或冲突的规则融入现有章节，展示目标绝对路径、作用范围和具体 diff。保留项目权限、发布规则和他人内容；不整文件替换、不重复添加同义规则。已有五项原则且无冲突时说明无需改动。
3. 等用户确认目标和该 diff 后再写入；本次对话已有对应明确确认则沿用。先保留原文件备份，写前重读，源文件变化则重新核对差异；不能用等待超时当同意。若用户拒绝修改，仍可按其授权使用小队。
4. 核对合并结果，按小队技能 `bind` 当前主会话，确认只使用固定 Qoder 成员，设计与验收在主会话，Plan 与嵌套代理禁用。不要为了初始化创建演示任务或 Codex 子会话。
5. 融合完成后执行插件 CLI `intro open`，用宿主浏览器打开返回的 GitHub Pages 产品介绍与使用说明。本会话的小队任务看板、分析、UED 和总结继续通过插件统一本机服务访问，不把私密会话地址写入公开介绍。介绍文案放介绍页资产，不写入技能或用户的 AGENTS.md。

只回报实际完成的配置位置、绑定结果和介绍链接；不把安装、登录、网络恢复或发布说成已经完成。需要页面设计与 Stitch 认证时，按同插件 UED 技能处理，不能代管凭据。

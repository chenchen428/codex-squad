# 功能验收

这是 Codex 小队内的测试与验收报告入口，随小队安装和发布，无需另装技能。主 Codex 确定验证范围、判断结果并独立核验；可独立执行的测试、取证和返工按[小队分工](../codex-squad/SKILL.md)交给 Qoder。报告使用小队内置的唯一模板和数据合同。

## 设计与执行测试

1. 从用户已确认的需求、原话、文档、设计和实际变更列出可观察完成条件。逐例说明为什么测、保护什么行为和参考来源：测新追溯新增或有意变化的需求；回归追溯既有规则、受影响路径或历史问题。来源不限 PRD，有链接就可跳转，无链接保留原话和出处。
2. 读取目标项目指令和实际测试入口，复用它的单测、集成测试、UI 操作、只读查询或已有回归工具。按当前变更选择能证明行为的检查；测试计划和模拟数据不能当实际结果。项目已有专用测试流程时沿其现有合同执行，不另造测试执行器或用报告 CLI 替代它。
3. 在用户授权的环境、账号与数据范围执行，记录命令或操作、环境、代码/制品版本、时间、入参、预期、实际和原始证据。未经授权不执行资金、业务写入、外发或生产操作。已有真实结果可复用时核对其版本与适用边界；只要求整理报告时不自动重跑业务。
4. 失败先区分产品、测试和环境原因，按事实修复或登记阻断，再重跑受影响部分。结果分别保留通过、失败、阻断、未执行和部分验证，不能靠减少范围、复制预期或只看构建成功判通过。影响代码或制品变化后，旧证据只保留为历史。

## 整理标准验收数据

用例按业务分组、目的和有序步骤组织。`caseDesign` 写用例缘由与参考来源；`caseRole` 区分测新、回归、兼有和执行审计；步骤的操作、预期、实际、状态和证据分别填写。执行审计不能混入产品失败数量。

页面使用真实截图；接口和数据步骤保留查询/调用原文、参数、返回及逐项对照。原文未留存时明确说明，重建模板标明重建；不补造执行记录。表格关注点显式定位结果集、行和字段，说明关注原因、预期、实际及证据，不因值相同自动判通过。

截图标注按原图坐标定位操作和核对区域，保留原图字节。前端改造关联真实 UED 图与原稿链接，缺失时登记材料缺口。界面变更先按[UED流程](../ued-designer/SKILL.md)取得 Stitch 导出再实现和核对；不把设计图当系统实拍。

中央主图默认直接显示标注，可隐藏并随缩放、平移对齐；不能只在放大层显示。每张图的文字应说明用户要核对哪里以及观察边界，风险框也是关注点。缺少实拍的步骤保留缺口，不能借别的状态截图填充。

复现入口跟随步骤，填写的外部地址必须实际核验；带入当前参数与环境，打开不自动执行。占位模板、历史不可重放与未授权写操作不能包装为一键复现。

## 生成 HTML 报告

本技能目录向上两级是插件根目录，`CLI` 是其 `cli/index.mjs` 绝对路径。生成命令无需小队绑定、npm install、业务服务或浏览器录制：

```sh
node CLI acceptance init ./acceptance-data --json
node CLI acceptance validate ./acceptance-data/acceptance.json --json
node CLI acceptance audit ./acceptance-data/acceptance.json --json
node CLI acceptance build ./acceptance-data/acceptance.json --out ./acceptance-package --require-quality --json
```

先按[数据合同](../../cli/lib/functional-acceptance/references/data-contract.md)整理输入，按[CLI说明](../../cli/lib/functional-acceptance/references/cli.md)校验和构建。默认 `inline` 生成图片内联的单 HTML；图片较多时使用 `--asset-mode external` 并交付完整目录与 `images/`。输出目录须不存在或为空，拒绝覆盖。

需要在本机查看已生成报告时，使用 `node CLI acceptance serve 验收包目录 --port 63352`。serve 只把验收包作为只读静态页面提供，只监听 127.0.0.1，启动前核对 manifest.json 与 index.html 的内容指纹，拒绝其它 Host、目录穿越和指向包外的符号链接。它不提供问答、云端接口或任何外部请求；离线 HTML 的 CSP 保持不变，报告数据始终来自包内 `#acceptance-data`。按 Ctrl+C 结束服务，交付时仍以本地 HTML 与完整目录为准。

Header 用 `report.links:[{label,url}]` 关联真实需求、PRD、变更单或其它来源。标签说清链接对象，实际打开核对目标身份；缺少来源链接时保留说明，不按编号拼造地址，不把链接存在当作正文已读。

任务只交标准 JSON 与证据，HTML、CSS 和查看器脚本只由模块维护，不补丁单份报告。`acceptance validate/build` 只验证输入和生成展示，不会执行项目测试、SQL 或 RPC，也不决定业务验收结果。

## Agent 内容验收（交付前必须执行）

Agent 必须实际阅读最终数据与关联证据，逐用例、逐步骤、逐核对项检查内容；不能用构建、规则通过或截图数量代替内容验收。

1. 先运行 `acceptance audit --json`，按 `repairTasks` 逐步骤补证并再次审计。已执行接口/数据/消息步骤必须绑定真实查询或调用原文（`origin=executed`）及能在该步显示的原始结果；右栏摘要、重建参数模板或“原文未留存”都不能通过完整性检查。页面须有实拍或原始浏览器观察。追溯已有工具记录、日志、查询审计及源文件，核对时间、环境、参数和SHA；不得从结果字段猜SQL，也不得用当前查询代替历史前置。确实找不回时保留阻断及修复任务，不生成合格报告。
2. 用例缺缘由/来源、空泛实际结果、通过状态冲突、图片无重点/越界、关注格不存在等错误必须修复。每项警告逐项复核并记录处置及影响；不得删除证据、改成示例或降低状态要求清零错误。真实报告的 `build` 默认执行质量门禁；`--require-quality` 也对示例执行，`audit --strict` 可使警告一并阻断。
3. 把预期、实际、逐项裁决与证据原文逐一对照：保留金额、状态、数量、时间、长整型和空值原义；验证该证据是否支持该结论。特别区分页面选择/确认/资金受理/到账终态，以及历史执行、当前版本、设计稿、实拍与模拟结果。发现“通过但证据不足”要修正表达或登记未验证，不能凭相似截图推断。
4. 核实为什么测及参考来源是否覆盖测新需求或回归风险；核查 Header、原始资料、用例引用、复现环境与预填参数。格式合法不证明链接可访问，复现入口打开不自动执行。
5. 浏览器检查实际可见内容：图片重点是否对齐、标签是否遮住关键值、局部说明与表格是否一致、关联链接是否跳对对象、助手是否仅据本报告回答。与设计在同状态核对；拖动后刷新检查位置记忆，来源页内跳转保持助手展开。
6. 保存随报告交付的 `content-review.md`，绑定最终输入SHA-256、版本、核验人/时间，逐项记录“完成条件→实际内容检查→证据→发现与修正→未验证边界”，附CLI质检结果及全部警告处置。未读或不可核验的材料记未知，不写成通过。Agent 内容核验完成与用户验收、业务准出、发布分别报告。

## 运行态核验与交付

实际打开生成的 HTML，核对分组与其他筛选的 AND 组合、计数、空态及步骤切换；核对 SQL/请求与结果同屏、关注格悬停/键盘说明、行详情及字段/整行原值复制。检查所有位置图片的放大、缩放、平移、标注、关闭与焦点恢复；核对来源跳转、UED 对照和复现链接的真实预填结果。

逐项交付“完成条件 → 实际测试 → 结果 → 证据 → 未验证边界”。明确区分实现、自测、主 Codex 独立核验、用户验收和发布；图片、测试数量或 HTML 生成成功都不能单独证明完整通过。提供 HTML 与完整资源包，不只给临时 localhost；发布外部报告入口仍遵守当前用户授权。

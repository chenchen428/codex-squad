# Codex 小队

[产品介绍与使用说明](https://chenchen428.github.io/codex-squad/)

- 主 Codex 负责需求、排查方向、方案取舍与 UED 设计、关键决策和独立验收。唯一执行成员为 `implementer`：Qoder / DeepSeek-Flash，负责完整调查、实现、自检与返工；不为设计或验收创建 Codex 子会话。历史 Codex 检查记录保留可读，不再派发或续接。
- 效率优先。把可独立验收的完整问题交给 Qoder，同步推进不重叠工作；复用证据，只传必要背景。不为凑并发拆碎任务、不重复探索。执行进程禁用 Plan 模式及嵌套代理，不递归组队。
- 本技能目录向上两层为插件根目录；下文 `CLI` 是其 `cli/index.mjs` 的绝对路径。在用户工作目录运行 `node CLI bind`，身份仅取宿主 `CODEX_THREAD_ID`；不猜其他会话，不绕过插件直接启动执行器或替换模型。

## 分工与调查

- 先判断是否值得派工：目标清楚、少量现成操作即可得到结果的任务由主 Codex 直接完成，例如命令是否存在、版本/帮助、登录状态、最小只读连通性检查及简单查找。不要为这类任务创建小队任务或交接报告，也不要先派工再由主线程重复执行。遇到需要持续调查、修改与验证的问题后，再把该完整问题交给 Qoder。
- 可独立验收且值得交接的代码理解、定位、复现、实现与自检优先交给 Qoder；主 Codex 先给目标、范围和验收条件，不先完整调查再让成员重查。同一问题从调查到实现、补证与返工沿原任务继续，不按阶段另建任务。可验收是派工前提，不是所有小任务都要派工的理由。
- 涉及跨模块状态、并发、业务规则或架构取舍时，主 Codex 确定关键假设和排查方向，必要时直接调查关键路径，再交给 Qoder 收集证据和验证；不为 Token 占比强行委派。
- 调查返回须给触发条件、调用路径与代码位置、复现或日志证据，以及尚未解释的现象。主 Codex 复核关键源码和原始结果，不把成员摘要当根因；证据不足就定向补查，补查仍不清楚时接手关键部分并说明原因，成员继续承担可独立完成的复现、测试或实现。
- 返回优先给结论、差异、实际检查结果、证据路径和剩余问题，按需取过程。主 Codex 按风险核对关键差异与实际行为；发现问题优先沿原任务修正，避免重新探索整个模块或直接补做大段实现。

## 交办与并发

`node CLI dispatch` 从 stdin JSON 接收：

```json
{"requestId":"stable-unique-id","memberId":"implementer","title":"完整问题","goal":"可观察结果","scope":["允许操作与禁止事项"],"writePaths":["src/feature.ts","test/feature.test.ts"],"criteria":["验证与交付证据"],"context":"必要背景与引用"}
```

- `writePaths` 为相对工作目录的确切文件或目录子树，不是 glob。列全共享依赖、配置与生成物；未声明时整个工作目录独占。范围重叠串行，不重叠可并发。它是调度合同，不是文件系统沙箱；主 Codex 写入也避开正在占用的范围。
- 单主会话同时执行最多 19 项，并发上限不是目标；遵守实际范围冲突与执行器限制，不用新通道、仓库副本或擅建 worktree 绕过。保留他人 WIP，委派不扩大提交、发布或对外发消息的授权。
- 正文用 stdin 文件或带引号 heredoc，不拼接 shell。相同 `requestId` 只查原交办；`running` 只是接单，仍需真实终态。
- 真实派发成功后，在主会话用一句话说明任务名、执行人并附返回的 `progressUrl`：`已创建「任务名」，交给 Qoder / DeepSeek-Flash。[查看进展](progressUrl)`。续接写“沿原任务继续”，重复回执不说新建；多项可合并一条提示，但每个任务名分别关联自己的详情直达链接（含 `#session/<taskId>`）；禁止用概览/看板地址代替任务进展链接。创建失败不宣布已派发；页面失败先说明已接单但链接待恢复，不编造链接、不重复创建任务。

## 收取、续接与验收

- `node CLI wait` 接收 `{"seconds":30,"after":"上次cursor"}`，有界等待变化；`snapshot` 取紧凑事实，`details` 接收 `{taskId,attemptId?}` 按需读公开详情。不要短间隔轮询或转述未变状态，不读取隐藏推理。
- 交付前先执行 `node CLI inbox`，核对未处理返回（待Codex核验 / Codex核验中）；没有新返回就不要虚报进展。它复用快照读模型，不扫描全部历史对话。
- 同一问题补充、答复或返工用 `continue`：`{taskId,requestId,goal,scope,criteria,context,writePaths?}`，只传增量，沿原任务与原生会话保留尝试和消耗；未给 `writePaths` 继承原范围。原会话不可恢复就报告，不冒充续接。
- 按真实失败阶段处理。网络恢复后才沿原会话重试；同一根因一次有依据的返工后重新评估或接手，不无界重试。范围冲突先看占用任务，不能删锁强行启动。
- `stop` 接收 `{taskId,reason}`。收到停止回执前仍为停止中；失联是未知，停止不回滚文件。
- 开始核对时用 `verify` 接收 `{taskId}` 登记本轮负责人核验（待Codex核验 → Codex核验中）。返工或新尝试后需重新核对，旧核验记录作为历史保留。
- 主 Codex 核对差异、实际验证、产物与剩余问题后，才用 `accept` 接收 `{taskId,files:["具体相对路径"],note:"验证与证据"}` 记录验收；未完成本轮 `verify` 不能验收。验收同时保存真实产物指纹与证据说明。
- 历史验收是“当时通过”的事实。核验后文件再变化只标注 `核验后已有变更`，不撤销验收、不退回核验中；没有真实核验/验收记录的旧完成态显示待核对，不按状态猜测补齐。
- 确定不再继续时用 `retire` 接收 `{taskId,outcome:"cancelled"|"superseded",reason,replacedBy?}` 记录原因；运行中的任务必须先停止并取得真实终止回执，不能把失联当成取消。看板只显示实际执行中、待核验和已核验的任务；失败、未知、停止、取消及被替代的任务不展示，仍由主 Codex 处置；原对话、尝试和用量记录保留。
- 用量仅用真实回执；缓存包含在输入中，不重复累计。未上报保持未知，成员局部合计不能称为完整成本或节省比例。

## 设计、页面与总结

- 功能测试、自测、回归与验收报告使用内置[功能验收技能](../functional-acceptance/SKILL.md)：设计有来源的用例，复用项目测试入口实际执行并整理证据，以 `node CLI acceptance init/validate/build` 生成离线 HTML 后独立核验。技能、模板和数据合同随小队统一安装和发布。

- 页面表达任务可提示启用同插件 [ued-designer](../ued-designer/SKILL.md)；用户已选择时直接使用。设计和验收留在主会话，执行交给 Qoder。用户采用以对话中明确决定或主动复制发回的结果为准。
- Stitch 设计必须先导出原始 DOM、CSS 与素材，再按稿一比一实现，并用同状态、同尺寸截图核对；仅参考风格或功能测试通过不能交付为视觉还原。
- `node CLI open` 返回本会话只读小队 URL，按需用宿主浏览器打开；URL 是本机访问凭据，不外发。`review open` 接收 `{directory}`，挂载已校验的本轮评审目录。
- 给用户交付验收会话时，准备该会话自己的真实任务、对话、过程、用量和页面入口；不能只给空绑定或别的会话示例。以实际安装的发布包核对版本和证据。
- `node CLI intro open` 返回 GitHub Pages 产品介绍与使用说明链接，不启动本机服务。初始化使用 [initialize](../initialize/SKILL.md)，先展示目标 AGENTS.md 的具体差异，再按用户确认融合。
- 仅在主会话收尾时使用 [session-summary](../session-summary/SKILL.md) 保存总结；子任务完成、普通轮次结束或阶段变化不触发。恢复上下文只按需读取；用户明确要求总结时随时执行。保存后只提示“会话总结已保存”及链接，不展开正文或自动开页。所有视图复用同一服务和端点，各会话隔离。

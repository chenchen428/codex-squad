# UED 设计师

- 这是主 Codex 的设计职责，不是执行成员。方案、UED 和独立验收在主会话完成；采用后的实现交给 `implementer / Qoder / DeepSeek-Flash`，不派发 designer 或 reviewer。
- 页面表达有价值时简短提示用户是否启用。用户已说用 Stitch、启用 UED 或出设计稿就直接继续，不重复确认；未选择时不创建云端项目或画面。
- 先发现当前宿主真实可用的 Stitch MCP。首次接入或认证失败按 [Stitch 接入](references/stitch-setup.md)，先引导用户自己用 Google 登录，再配置 MCP 并只读验证；不代管密码、密钥或验证码，不编造工具或成功回执。
- 读取实际 DESIGN.md、品牌、字体、主题和控件状态，复用匹配的 Stitch 项目与设计系统。没有现成系统时形成精简 DESIGN.md，区分既有事实与本轮选择。按实际 MCP 合同上传、建立并应用设计系统，回读核对真实 asset/screen 身份；本地文档不等于已应用。
- 锁定采用方案、版本、页面状态与原始视口；用户最终修订优先于历史稿。已有采用和实施授权就继续，不重新设计或重复选稿。先核心路径与必要状态，再扩展画面；不伪造业务数据。
- 尊重 Stitch 首次设计产物，保留其布局、信息层次、视觉特色与细节；不以“轻量、效率、易实现”为由擅自简化、套模板或重画。发现业务缺项时保留首稿，在其结构上局部补全并重新导出；显著改动设计须由用户决定，不能把减少功能与削弱设计混为一谈。
- 生成超时或断连时先查原请求结果和画面身份，取得明确失败且工具允许后才有限重试，不重复生成。材料外发遵守当前授权。
- 需要选稿时按 [评审接入](references/review-workflow.md) 使用同插件 [stitch-review](../stitch-review/SKILL.md)，经校验后挂载到插件统一服务。采用仅以用户对话中的明确决定或主动复制发回的结果为准，不读取正常页面、存储或剪贴板推断。
- **必须先导出，再一比一还原。** 从准确 Stitch screen 导出原始 HTML、CSS、字体、图标和图片，保存 screen/file 身份与指纹，直接按导出 DOM 移植。Stitch 稿是实现基准，不是风格参考；禁止凭截图重画、换组件近似或用整页截图充当界面。导出缺失就补齐或报告具体阻塞，不能自行降级为模仿。
- 主 Codex 在相同浏览器、视口、DPR、状态和数据下提交设计/实现的同尺寸截图及叠加或差异图，逐项核对字体、字重、字号、行高、间距、颜色、尺寸和换行，不能靠缩放适配。未对齐继续修正；构建和功能测试通过不能代替视觉还原，未解决的差异不能宣称完成。
- 交付实际设计来源、运行入口、实现与验证证据、剩余差异；静态稿与运行功能分别说明。客户介绍与截图放产物，不扩写技能。
